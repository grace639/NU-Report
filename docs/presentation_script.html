1. Intro — สมาชิกคนที่ 1 ≤ 5 นาที

เปิดตัว (30 วินาที)

สวัสดีครับ/ค่ะ กลุ่มเราทำแอป NU Report ระบบแจ้งปัญหาภายในอาคาร สมาชิกมี 4 คน รหัส ........, ........, ........ และ ........ เดี๋ยวขอเล่าโจทย์และภาพรวมก่อน แล้วแต่ละคนจะสาธิตส่วนที่ตัวเองทำครับ/ค่ะ

โจทย์และผู้ใช้ (1 นาที 30 วินาที)

ผู้ใช้ของเราคือ ชื่อ-ตำแหน่ง ผู้ใช้จริง จาก หน่วยงาน ปัญหาตอนนี้คือ วิธีแจ้งปัญหาปัจจุบัน เช่น แจ้งปากเปล่า/โทร/กลุ่ม LINE ทำให้ ผลเสียที่ผู้ใช้เล่า เช่น เรื่องตกหล่น ไม่รู้ว่าซ่อมหรือยัง ปลายเดือนต้องนับเอง
เราไปพบผู้ใช้ N ครั้ง ครั้งที่ ... วันที่ ... ผู้ใช้ขอให้ สิ่งที่ผู้ใช้ขอ เราจึงแก้เป็น สิ่งที่เปลี่ยนจริง รายละเอียดอยู่ใน change log ของฟอร์ม 3

ส่วนนี้ได้คะแนน A1 ตรงที่สุด ใช้คำพูดจริงจากฟอร์ม 2

ความต้องการ R1–R6 (1 นาที 30 วินาที)

จากที่คุยกับผู้ใช้ เราได้ความต้องการ 6 ข้อ แต่ละข้อมีเกณฑ์ว่ากดอะไรแล้วต้องเห็นอะไร
รหัสความต้องการผู้รับผิดชอบ
R1แจ้งปัญหาพร้อมรูปถ่ายและสถานที่คนที่ 2
R2ค้นหาและกรองเรื่องที่เคยแจ้งคนที่ 1
R3เจ้าหน้าที่เปลี่ยนสถานะพร้อมหมายเหตุคนที่ 3
R4ผู้แจ้งรู้ทันทีเมื่อเรื่องมีความคืบหน้าคนที่ 4
R5สรุปผลรายเดือนเป็นกราฟและส่งออก CSVคนที่ 4
R6เจ้าหน้าที่ประกาศข่าวให้ผู้ใช้ทุกคนคนที่ 2

ภาพรวมเทคนิค (1 นาที)

แอปทำด้วย Flutter ข้อมูลเก็บในเครื่องด้วย SQLite ผ่าน package sqflite เพราะต้องค้นหาและกรองตามหลายเงื่อนไข และใช้ได้แม้ไม่มีอินเทอร์เน็ต
สถานะของแอปจัดการด้วย Provider มีสองตัว ตัวแรก AuthProvider เก็บว่าใครล็อกอินอยู่ ตัวที่สอง ReportProvider เก็บรายการเรื่อง พอข้อมูลเปลี่ยน ทุกหน้าที่ใช้ข้อมูลนั้นจะอัปเดตตามทันที
งานที่ใช้เวลา เช่น อ่านฐานข้อมูลหรือเปิดกล้อง เราแสดงสถานะกำลังโหลดและปิดปุ่มไม่ให้กดซ้ำ ถ้าเกิดข้อผิดพลาดจะขึ้น SnackBar สีแดงพร้อมปุ่ม "ลองใหม่" และใน repository ไม่มีคีย์หรือรหัสผ่านจริง มีแค่บัญชีทดสอบ
ปิดท้ายว่า "ต่อไปคนที่ 2 จะสาธิตการแจ้งปัญหา" แล้วล็อกอิน user / user123 ส่งเครื่องให้คนที่ 2

2. สมาชิกคนที่ 2 — R1 แจ้งปัญหา · R6 ประชาสัมพันธ์ ≤ 5 นาที

R1 แจ้งปัญหา (2 นาที 30 วินาที)

ส่วนของผมคือหน้าแจ้งปัญหา ธีมของแอป และหน้าประชาสัมพันธ์ เริ่มจากผู้ใช้กดปุ่ม "แจ้งปัญหา" ที่มุมขวาล่าง
กดปุ่ม "แจ้งปัญหา" → กด "ส่งเรื่อง" ทันทีโดยไม่กรอกอะไร
ถ้าไม่กรอก ฟอร์มจะไม่ยอมส่ง และบอกว่าช่องไหนขาด ใช้ Form กับ validator ของแต่ละช่อง รายละเอียดต้องยาวอย่างน้อย 10 ตัวอักษร เพื่อให้เจ้าหน้าที่ได้ข้อมูลพอ
แตะกรอบรูป → "ถ่ายรูป" → ถ่าย → กรอกหัวข้อ "แอร์ไม่เย็น" · หมวด "ไฟฟ้า" · สถานที่ "SC2 ห้อง 301" · รายละเอียด → "ส่งเรื่อง"
ระหว่างบันทึก ปุ่มเปลี่ยนเป็น "กำลังบันทึก..." และกดซ้ำไม่ได้ ป้องกันเรื่องซ้ำ พอสำเร็จจะเด้งกลับมาหน้ารายการ และเห็นเรื่องใหม่บนสุดด้วยสถานะ "รอดำเนินการ" ทันที
lib/screens/create_report_screen.dart ฟังก์ชัน _submit() และ lib/services/image_service.dart
จุดสำคัญคือรูป package image_picker คืนไฟล์ที่อยู่ในโฟลเดอร์ cache ซึ่งระบบลบทิ้งได้ เราเลย copy รูปไปเก็บในโฟลเดอร์ของแอปเองก่อน แล้วค่อยเก็บ path ลงฐานข้อมูล รูปจะไม่หายภายหลัง และย่อรูปเหลือกว้าง 1280 px เพื่อไม่ให้ไฟล์ใหญ่

R6 ประชาสัมพันธ์ (2 นาที)

ล็อกเอาต์ → ล็อกอิน admin / admin123 → แท็บ "ประชาสัมพันธ์" → "ประกาศใหม่" → หัวข้อ "ปิดน้ำประปา ส. 25 ต.ค." · เนื้อหา · ติ๊ก "ปักหมุดไว้บนสุด" → "เผยแพร่"
เจ้าหน้าที่ประกาศข่าวได้ ประกาศที่ปักหมุดจะอยู่บนสุดและมีกรอบสีแสด ใช้ SQL ORDER BY pinned DESC, created_at DESC คือเรียงที่ปักหมุดก่อน แล้วตามด้วยใหม่สุด
กด ⋮ ที่ประกาศต้อนรับ → "เลิกปักหมุด" ให้เห็นว่าลำดับเปลี่ยน → ล็อกเอาต์ → ล็อกอิน user → แท็บ "ประชาสัมพันธ์"
ฝั่งผู้ใช้เห็นประกาศเดียวกัน แต่ไม่มีปุ่มสร้าง ลบ หรือปักหมุด เพราะหน้าจอเช็ก isAdmin จาก AuthProvider

ธีม (20 วินาที)

สีของแอปเป็นเทา-แสดตามสีมหาวิทยาลัย รวมไว้ที่ lib/theme/app_theme.dart ไฟล์เดียว หน้าอื่นเรียกผ่าน Theme.of(context) ถ้าจะเปลี่ยนสีก็แก้ที่เดียว
ส่งเครื่องให้คนที่ 1 โดยล็อกอิน user ค้างไว้

คำถามที่อาจโดน

ถ้ากดส่ง 2 ครั้งเร็วๆ จะได้ 2 เรื่องไหม
ไม่ได้ ตัวแปร _saving เป็น true ตั้งแต่เริ่มบันทึก ปุ่มจะได้ onPressed: null จึงกดไม่ได้จนกว่าจะเสร็จ และ finally คืนค่ากลับแม้บันทึกล้มเหลว
ถ้าผู้ใช้ไม่อนุญาตกล้องจะเกิดอะไร
_pickImage ครอบด้วย try/catch ถ้า error จะขึ้น SnackBar สีแดงว่าเปิดกล้องไม่ได้ ฟอร์มยังอยู่ ส่งเรื่องโดยไม่แนบรูปได้ เพราะรูปไม่บังคับ
mounted ที่เช็กหลัง await คืออะไร
ระหว่างรอบันทึก ผู้ใช้อาจกดย้อนกลับไปแล้ว หน้าจอถูกทำลาย ถ้าเรียก context ต่อจะ error จึงเช็ก mounted ก่อนใช้ context ทุกครั้งหลัง await
ทำไมต้องใส่ heroTag ที่ปุ่มประกาศใหม่
Flutter ใช้ heroTag ทำอนิเมชันตอนเปลี่ยนหน้า ถ้ามีปุ่มลอยสองปุ่มที่ tag ซ้ำกันในเส้นทางเดียวกันจะ error จึงตั้ง tag แยกให้ไม่ชนกัน

คำถามเฉพาะหน้า: "เปลี่ยนให้รูปเป็นสิ่งที่บังคับ" → เพิ่มเช็ก if (_imagePath == null) ใน _submit() แล้ว showError และ return

3. สมาชิกคนที่ 1 — R2 ค้นหา · ฐานข้อมูล ≤ 5 นาที

R2 ค้นหาและกรอง (2 นาที)

ส่วนของผมคือฐานข้อมูลและการค้นหา เมื่อเรื่องเยอะขึ้น ผู้ใช้ต้องหาเรื่องที่เคยแจ้งได้เร็ว
พิมพ์ "น้ำ" ในช่องค้นหา → รอให้รายการเหลือ "ก๊อกน้ำรั่ว" → กด ✕ ล้าง
ค้นทั้งหัวข้อ รายละเอียด และสถานที่พร้อมกัน แอปรอให้หยุดพิมพ์ 400 มิลลิวินาทีค่อยค้น เรียกว่า debounce จะได้ไม่ query ฐานข้อมูลทุกครั้งที่กดตัวอักษร
กดชิป "รอดำเนินการ" → เลือกหมวด "ไฟฟ้า" → กด "ทั้งหมด" และ "ทุกหมวด" คืน
กรองตามสถานะและหมวดหมู่ซ้อนกับคำค้นได้ ดึงลงเพื่อโหลดใหม่ก็ได้

โครงสร้างฐานข้อมูล (2 นาที 30 วินาที)

lib/db/database_helper.dart ฟังก์ชัน _onCreate
มี 5 ตาราง users, categories, reports, comments สำหรับประวัติการดำเนินการ และ announcements สำหรับประชาสัมพันธ์ ตาราง reports อ้างถึง users และ categories ด้วย foreign key ต้องสั่ง PRAGMA foreign_keys = ON ทุกครั้งที่เปิด เพราะ SQLite ปิดไว้เป็นค่าเริ่มต้น
มี index ที่ user_id และ status เพราะเป็นสองคอลัมน์ที่ค้นบ่อยที่สุด และฐานข้อมูลเปิดแบบ Singleton คือทั้งแอปมีตัวเดียว
lib/db/report_dao.dart ฟังก์ชัน search()
ฟังก์ชันนี้ต่อเงื่อนไข WHERE ตามที่ผู้ใช้เลือก ถ้าไม่ได้เลือกสถานะก็ไม่ใส่เงื่อนไขนั้น ค่าที่ผู้ใช้พิมพ์ส่งผ่านเครื่องหมาย ? ไม่ต่อลง SQL ตรงๆ จึงกัน SQL injection ได้
และใช้ JOIN ดึงชื่อหมวดหมู่และชื่อผู้แจ้งมาใน query เดียว ไม่ต้องยิงหลายรอบ
ส่งเครื่องให้คนที่ 3

คำถามที่อาจโดน

ทำไมใช้ SQLite ไม่ใช้ไฟล์ JSON หรือ SharedPreferences
ต้องค้นหาตามคำ กรองตามสถานะและหมวด และนับสถิติด้วย GROUP BY ถ้าใช้ JSON ต้องโหลดทั้งไฟล์มาวนเองทุกครั้ง SQLite ทำในคำสั่งเดียวและมี index
ถ้าจะเพิ่มคอลัมน์ priority ต้องแก้อะไรบ้าง
เพิ่มใน CREATE TABLE, เพิ่มฟิลด์ใน Report ทั้ง fromMap/toMap, เพิ่ม _dbVersion เป็น 3 และเขียน onUpgrade ให้ ALTER TABLE reports ADD COLUMN priority ... แบบเดียวกับที่เราทำตอนเพิ่มตาราง announcements ในเวอร์ชัน 2 ข้อมูลเดิมในเครื่องผู้ใช้จะไม่หาย
ทำไมเก็บวันที่เป็น string
SQLite ไม่มีชนิดวันที่ เราเก็บเป็นรูปแบบ ISO-8601 เช่น 2026-10-24T09:00 ซึ่งเรียงตามตัวอักษรแล้วตรงกับเรียงตามเวลา จึงใช้ >= และ < หาช่วงเดือนได้
ทำไม _db เก็บเป็น Future ไม่ใช่ Database
ตอนเปิดแอปครั้งแรก มีสองส่วนเรียกฐานข้อมูลพร้อมกัน ถ้าเก็บ Database จะเปิดสองครั้งระหว่างที่ยังสร้างตารางไม่เสร็จ (เคยเป็นบั๊ก รายการว่างตอนเปิดครั้งแรก) พอเก็บ Future ทุกคนรอตัวเดียวกัน
notifyListeners() ทำอะไร
บอกทุก widget ที่ watch provider นี้ว่าข้อมูลเปลี่ยนแล้ว ให้ build ใหม่ หน้ารายการจึงอัปเดตเองหลังค้นหาหรือเพิ่มเรื่อง
